# CAPACITY CONNECT implementation audit

## Scope and evidence
The supplied post-repair suite executed 24 tests successfully: 23 passed and one disposable-database test was skipped (the runner total includes the skipped test). The cancellation regression passed, confirming normal cancellation propagates without error logging or provider/database work. A separate managed-database transaction test verified real recipient scoping and duplicate prevention: the first enqueue matched the one eligible recipient, the repeated enqueue created zero duplicates, and the transaction was rolled back. This separate check does not replace the skipped disposable-database test or establish concurrency safety. Both managed migrations were applied. No external email was sent. Browser, concurrency, upload-storage, production scheduler and provider-delivery testing remain outstanding. Tests are not a penetration-test certificate.

## Delivery behavior and boundaries
Business changes enqueue durable email records in their current transaction. Transport runs separately after commit. Duplicate logical deliveries use deterministic identities and a database uniqueness conflict guard. A notice is created only for a newly inserted delivery. Notifications are currently individual-user notices, including announcement recipients, rather than one shared audience broadcast. Summaries are fixed. Event-specific titles use bounded names read from source records; result and grading titles resolve the associated assessment or assignment, and certificate titles resolve the course. Header control characters are removed and HTML content is escaped. Messages do not copy assessment answers, private evidence, free-text grading feedback, client-supplied scores, or announcement bodies. HTML is escaped; action destinations are allowlisted.

The scheduled worker and manual processing use bounded dispatch batches. Accepted records mean provider acceptance only, never inbox delivery or a read receipt. Ambiguous acceptance and stale claims are held for reconciliation, not automatically resent: provider idempotency expires after 24 hours, so automatic stale resends could duplicate a previously accepted message. Explicit transient responses use bounded backoff. There is no delivery webhook or open-tracking claim.

Known prerequisite: the supplied read-only account check confirmed that the connected Resend account has **zero verified sending domains**. Verify a sending domain before live delivery. Until then, discovery cannot select a sender and queued records become blocked with `sender_domain_unverified`. No test sender is substituted. Explicit sender configuration still requires provider authorization; the application does not create domains.

## Security findings
- Removed the predictable signing fallback. Timestamped signatures reject malformed, future, expired and tampered tokens; legacy tokens are invalidated.
- Added a nullable lockout timestamp and bounded failed-login lockout. Both managed migrations, covering login lockout and email delivery records, were applied.
- Added SameSite=Lax and environment-dependent Secure to the existing cookie. **HttpOnly remains unresolved**: Reflex client-managed cookies cannot honestly enforce HttpOnly. Move authentication issuance and retrieval to server-managed HTTP endpoints, with CSRF protection and websocket identity binding, before claiming this requirement complete. Do not add a fake HttpOnly flag to a JavaScript cookie.
- Delivery mutations re-check approved, active administrator identity. General legacy authorization paths were not all rewritten or exhaustively tested.
- Removed public display of newly generated password-reset links. Secure recovery delivery is not implemented by this transactional notification service, which deliberately excludes reset tokens. Administrator-assisted recovery is the current guidance.
- Account approval/status events permit inactive recipients at enqueue and dispatch, but dispatch still requires an existing user and exact current-email/snapshot equality. All other events continue to exclude inactive recipients. Successful login now assigns the current timestamp before commit while resetting lockout counters; generic invalid-credential responses are unchanged.
- Public announcement queries exclude future publication times. Future immediate-publication requests fail validation; edits moving publication into the future unpublish the record, and manual publish refuses future dates. Enqueue also independently rejects unpublished/future announcements. Existing fields do not distinguish a future draft from an approved scheduled announcement; no automatic scheduled publication is invented. Administrators must publish manually when due. Previously queued snapshots are not retroactively rewritten when source records change.
- Normal worker cancellation propagates without error logging; the post-repair cancellation regression passed. Sender-domain-unverified deliveries remain durable, blocked and administrator-retryable; no test sender is substituted.
- Existing development/demo access and automatic certification policy require a separate production review. Automatic issuance still follows existing completion behavior; this pass does not certify that policy as equivalent to reviewed certification.
