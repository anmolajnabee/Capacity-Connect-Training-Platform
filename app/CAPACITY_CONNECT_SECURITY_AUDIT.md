# CAPACITY CONNECT — Security audit

Document path: `app/CAPACITY_CONNECT_SECURITY_AUDIT.md`. Repository-root writing is not supported for this update; all five artifacts are under `app/`.

## Scope and release decision

**Not production-ready.** The protected resource-storage and certificate-workflow repairs are implemented in the application; this documentation update makes no further application changes. Fixes below describe earlier repairs evidenced by the supplied source and test history. Supplied tests are bounded unit, contract and handler checks, not a comprehensive penetration test. No secret values, passwords, session values, certificate tokens, connection values or deployment internals are recorded here.

Status vocabulary: IMPLEMENTED, PARTIALLY_IMPLEMENTED, MISSING, BROKEN, INSECURE, MOCKED, NOT_VERIFIED. A control may exist while the encompassing feature remains insecure.

## Findings, earlier fixes and acceptance gates

| Area | Status | Finding and earlier repair evidence | Remaining work / release acceptance |
|---|---|---|---|
| Auth/session cookie | INSECURE | **RELEASE BLOCKER:** session cookie remains client-managed and non-HttpOnly. Signature validation, expiration, SameSite and conditional Secure controls do not prevent JavaScript access. | Replace with a genuinely server-managed HttpOnly session mechanism; validate CSRF defenses, identity binding and session lifecycle. Do not simulate HttpOnly on a JavaScript cookie. Test script access, invalid sessions, logout and replay. |
| Protected resource storage and downloads | PARTIALLY_IMPLEMENTED | Resource bytes are stored outside Reflex’s public upload directory; bounded filenames and paths, 50 MB read/write limits, private round-trip tests and fresh role-scoped server-event retrieval are implemented. Frontend payloads do not expose stored filenames and direct `rx.get_upload_url` use was removed. A subsequent bounded live check with valid trainer and trainee sessions denied a nonexistent resource ID for both roles with the same generic unavailable message and no path/filename disclosure. | This negative check is not exhaustive IDOR coverage or deployed-download validation. Deployment storage durability, large-file delivery behavior, malicious-content scanning and post-deploy persistence remain NOT_VERIFIED. Production must configure `CC_PRIVATE_UPLOAD_DIR` as durable non-public storage with least-privilege filesystem access. |

No claim of a complete credential-stuffing defense. |
| Session validity and revocation | PARTIALLY_IMPLEMENTED | Expired, tampered, malformed, future and legacy signatures are rejected in supplied tests. Fresh role validation rejects invalid identity and checks current approval/activity rather than trusting cached role fields. | **Gap:** complete all-session revocation is not established. ## Test interpretation

Final supplied suite: 47 tests, 46 passed, one disposable-database test skipped, zero failures or errors. The 24-test baseline and historical 35-test run remain evidence; the 35-test run was 33 passed, 1 skipped, 1 failure and 0 errors, with the skipped test not run. The final regression contracts include preventing demo-password data from entering frontend portal options; server-side assessment locking, expiry, enrollment, persisted-option scoring and competency linkage; draft-only mutation; and token-only certificate lookup. The earlier failing 35-test demo-catalog assertion is historical evidence of a repaired issue, not omitted evidence. Mocked authorization/transport checks are not real browser or provider verification. The live Gemini probe establishes bounded endpoint responsiveness, not resistance to adversarial prompting.

## Remediation priorities

1. Resolve the remaining INSECURE client-managed non-HttpOnly session-cookie blocker before handling private production records.
2. Close password-recovery delivery and complete session-revocation gaps; execute negative access-control and session-replay tests.
3. Test official assessment, trainer allocation, enrollment and certificate issuance races in an isolated disposable environment.
4. Complete adversarial input, AI privacy, protected-download, large-file delivery and public-certificate tests, including malicious-content scanning.
5. Configure and independently validate durable private storage, post-deploy persistence, real authorized email delivery and production operation.

Browser security interaction, concurrency, real email delivery, deployment storage durability, large-file delivery, malicious-content scanning, post-deploy persistence and production deployment remain NOT_VERIFIED. No release approval is given.
